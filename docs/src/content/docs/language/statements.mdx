Statements are separated by newlines. Semicolons (`;`) can also be used to place multiple statements on a single line:

```sysl
a[0] = 1; a[1] = 2; a[2] = 3
val x = 10; val y = 20
```

## if / elif / else

```sysl
if x > 0
    positive()
elif x == 0
    zero()
else
    negative()

// if-then (inline)
if x > 0 then positive()
```

`if` is also an expression — `val v = if x > 0 then x else -x` works. See [Expressions](/language/expressions#if-expression).

## match

Value-based pattern matching with no fallthrough. Each arm has a pattern, an optional guard, and a body:

```sysl
x match
    1 -> doA()
    2, 3 -> doB()              // multiple values per arm
    _ -> doDefault()           // wildcard (matches anything)
    else -> doDefault()        // alternative to wildcard

// match as expression
y = x match
    1 -> "one"
    2, 3 -> "few"
    else -> "many"
```

### Guards

```sysl
x match
    _ if x > 10 -> "big"
    _ if x > 0 -> "positive"
    else -> "non-positive"
```

### Range matching (inclusive)

```sysl
x match
    1..10 -> "small"
    11..100 -> "medium"
    else -> "large"
```

### Struct destructuring

```sysl
p match
    Point(x, y) -> x + y      // binds x and y from fields
    Point(_, y) -> y           // wildcard ignores field
    Point(x, y) if x == 0 -> y  // guard with bindings
```

### Tagged union matching

```sysl
s match
    Circle(r) -> r * r * 3    // match variant, bind fields
    Rect(w, h) -> w * h
    Empty -> 0                 // no-data variant
    Circle(r) if r > 5 -> 1   // guard with variant binding
```

Exhaustive on enums — see [Enums](/language/types/enums#exhaustiveness).

### Tuple patterns

```sysl
t match                       // t: (int, int)
    (a, b) -> a + b
    (a, _) -> a               // wildcard at any position

// Nested tuple inside a variant
r match                       // r: Result with Ok(p: (int, int))
    Ok((a, b)) -> a + b       // tuple field destructured in place
    Err(_) -> 0
```

### Block bodies

```sysl
x match
    1 ->
        a = compute()
        doSomething(a)
    else -> fallback()
```

## Loops

### while

```sysl
while cond
    body

// while-do (inline)
while i < 10 do i++
```

### do-while

```sysl
do
    body
while cond
```

### loop (infinite)

Ada-style infinite loop; exit only via `break` (or `return`):

```sysl
loop
    if done then break
    body
```

### C-style for

```sysl
for i = 0; i < 10; i++
    body

// for-do (inline)
for i = 0; i < 10; i++ do sum += i
```

### for-in range

```sysl
// Inclusive — includes upper bound
for i in 1..5
    body                       // i takes 1, 2, 3, 4, 5

// Exclusive — excludes upper bound
for i in 0..<5
    body                       // i takes 0, 1, 2, 3, 4

// Inline
for i in 0..<n do print(i)
```

### Counting down

```sysl
for i in 10 downTo 0
    body                       // i takes 10, 9, ..., 0
```

### Step

```sysl
for i in 0..100 step 5          // 0, 5, 10, ..., 100
for i in 0..<30 step 3          // 0, 3, 6, ..., 27
for i in 20 downTo 0 step 4     // 20, 16, 12, 8, 4, 0
```

### Iterate over arrays / slices / strings

```sysl
for v in arr
    body                       // v = each element

// Iterate backward
for i in reverse Day::Range    // last variant down to first
for v in reverse arr           // index len-1 down to 0

// Iterate with index and value
for i, v in arr
    body                       // i = index, v = arr[i]
```

### Range membership operator

```sysl
x in 1..4                       // true if 1 <= x <= 4 (inclusive)
x in 1..<4                      // true if 1 <= x < 4  (exclusive)
x !in 1..4                      // negated membership
if score in 90..100 then grade = 'A'
```

### break and continue

```sysl
while true
    if done then break
    if skip then continue
    process()
```

## Loop contracts

### `variant <expr>` — loop termination witness

The expression must strictly decrease between iterations and stay ≥ 0. On the first iteration nothing is checked; on every subsequent one the analyzer-emitted check traps if either condition is violated:

```sysl
var remaining = 100
while remaining > 0
    variant remaining          // monotonic-decrease witness
    remaining = remaining - step()
```

Must appear at the top level of a loop body.

### `invariant <bool>` — loop invariant

Ada/SPARK-style loop invariant. Must appear in the leading "header" of a loop body (variants may interleave); the analyzer hoists the check to the loop's *cut point* and runs it at the top of every iteration:

```sysl
for i = 0; i < n; i++
    invariant i >= 0
    invariant i <= n, "i in range"   // optional message
    body()
```

Multiple invariants are allowed; all are checked. A false invariant traps with `loop invariant check failed[: msg]`.

An invariant placed after a non-invariant statement, nested inside an `if`/`match`, or outside any loop is a static error.

Invariants and variants can be freely interleaved in the leading header.

### `loop_entry(expr)` — entry snapshot

Valid only inside a loop invariant. Captures the value of `expr` once, at the moment control first reaches the loop, so subsequent invariant evaluations can compare against the entry value:

```sysl
var x = 0
for i = 0; i < n; i++
    invariant x >= loop_entry(x)            // monotonic non-decrease
    invariant loop_entry(i) == 0            // i started at 0
    x = x + i
```

Each enclosing loop has its own snapshot scope. `loop_entry(expr)` outside a loop invariant — including in an `ensure` clause or in loop-body code — is a static error. Use `old(expr)` for the function-entry snapshot.

## Labeled loops

`break` / `continue` can target an outer loop by name. A label is an identifier followed by `:` immediately before `for`, `while`, `do`, or `loop`:

```sysl
outer: for i in 0..<n
    for j in 0..<m
        if grid[i][j] == target then break outer      // exits both loops
        if grid[i][j] == 0 then continue outer        // next iteration of outer
        use(grid[i][j])
```

Unlabeled `break` / `continue` always target the innermost enclosing loop, regardless of whether that loop has a label.

A label cannot be reused on a nested loop (would make `break label` ambiguous), but the same name can appear on sibling (non-nested) loops.

## end markers

Every block construct accepts an optional matching `end <keyword>` after its body — Scala 3 style. Useful for long blocks where the matching indentation is hard to see; always optional:

```sysl
if cond
    big_body()
end if

while running
    tick()
end while

for i = 0; i < n; i++
    process(i)
end for

loop
    if done then break
    work()
end loop

x match
    1 -> "one"
    else -> "other"
end match

struct Point
    x: int
    y: int
end struct

enum Color
    Red
    Green
    Blue
end enum

trait Eq[T]
    eq(self: T, other: T) -> bool
end trait

impl Eq[int]
    eq(self: int, other: int) -> bool = self == other
end impl

interface Closer
    close() -> int
end interface
```

The compiler doesn't verify the name matches the construct — `end if` after a `while` parses fine — but typos make the file harder to read.

## Destructuring and parallel assignment

Tuples can be destructured with or without parentheses (Go/Python style):

```sysl
// Declaration (new variables)
q, r = divmod(17, 5)           // Go-style, creates q and r as var
(q, r) = divmod(17, 5)         // parenthesized form also works
val q, r = divmod(17, 5)       // immutable
var q, r = divmod(17, 5)       // explicit mutable

// Parallel assignment (existing variables)
a = 10
b = 20
a, b = b, a                    // swap: RHS fully evaluated before assignment

// Works on named structs too (not just tuples)
p = Point(10, 20)
x, y = p                      // x = p.x, y = p.y (field order)

// And ref structs
r = new Point(3, 4)
a, b = r                      // a = 3, b = 4

// Mixed declared/undeclared is an error
a = 10
a, b = 20, 30                  // ERROR: a exists but b doesn't
```

Rules for `a, b = ...` without `val`/`var`:

- All names new → declaration as `var`
- All names exist as `var` → parallel assignment
- Mixed → error

## return

```sysl
return              // unit return
return expr         // return single value
return a, b         // return tuple (no parens needed)
// or: last expression in block is implicit return
```

## Inline assembly

```sysl
asm("halt")
asm("trap 0")
```

The string is emitted verbatim into the assembly output. Only the TRISC and SVM backends accept inline asm; LLVM backends reject it (use `extern` for low-level interop).
